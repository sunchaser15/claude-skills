# Секции страницы: назначение, макеты, правила честности

Фильтр antislop главнее этого файла. Здесь нет «обязательного порядка лендинга»: порядок, состав и число секций определяются **реальным содержимым продукта** (C-3, R-05). Секция, для которой нет настоящего материала, не создаётся. Пустая секция лучше выдуманной (R-38).

Для каждой секции перед сборкой отвечай одним предложением: **зачем она здесь, и что в ней настоящее**. Если ответа нет, секции нет. Записывай это в таблицу композиции в `DESIGN.md`.

## Что нельзя делать по умолчанию (повторение главных запретов)

| Шаблон | Что делать вместо |
|---|---|
| Полоса «Нам доверяют» с логотипами | Только реальные клиенты с их согласия. Нет таких, нет полосы (R-18, R-36) |
| Отзывы с аватарками и именами | Только настоящие, с источником. Нет, нет секции (R-18) |
| «10 000+ пользователей», «99,9% аптайм» | Только цифры с реальным источником. Нет данных, нет цифр (R-17) |
| FAQ из шаблонных вопросов («Безопасны ли мои данные?») | Только вопросы, которые правда задают про этот продукт. Не знаешь вопросов, нет FAQ (R-28) |
| Три тарифа, средний с плашкой «Популярный» | Столько тарифов, сколько есть на деле; выделять только тот, что служит цели продукта, и записать почему (R-05, R-31) |
| «Как это работает» ровно из трёх шагов с круглыми иконками | Реальный процесс: два шага или пять, формой, которую диктует процесс (R-05) |
| Bento-мозаика как стандартная раскладка | Только если у содержимого действительно разные размеры; иначе простой список или сетка (R-05) |
| Три одинаковые карточки с иконкой | Одна главная возможность крупно, остальные списком (R-14) |
| Подвал из 4 колонок Продукт/Компания/Ресурсы/Право | Столько ссылок, сколько реально есть (R-05) |
| Бейдж-капсула над заголовком («Новинка», «AI») | Не нужна; заголовок говорит сам (R-09) |
| Стрелка → на каждой кнопке | Только если у неё есть смысл и размер (R-08) |
| Терминал-имитация в герое | Настоящий скриншот или видео продукта (R-05) |
| Ссылки в меню на страницы, которых нет | Только существующие якоря и страницы (R-24) |

## Шапка
Логотип (настоящий, от владельца, пока нет: название текстом или `[ЛОГОТИП]`, R-23), только ссылки, которые ведут на существующие секции, одна главная кнопка при необходимости. Цели нажатия ≥ 44 px. На телефоне ссылки не прячутся в «голый гамбургер»: если ссылок 3–5 и они короткие, показывай их строкой под логотипом; если больше, делай меню с подписью «Меню», закрытием по Esc и фокусом внутри. Залипающая шапка не должна съедать больше ~64 px высоты на телефоне.

## Герой (первый экран)
Задача: за 5 секунд понять, что это, для кого и что делать. Состав: **заголовок с результатом** (конкретика, цифры только настоящие) → **одна-две строки пояснения** → **одно главное действие и, при необходимости, второе** → **настоящий визуал** (скриншот продукта, фото, шейдер как атмосфера).
```
левый край ─ заголовок крупно (2–3 строки)
             пояснение
             [главное действие]  второе
             ───────────── визуал справа или фоном
```
Варианты, из которых выбираешь по характеру бренда (DESIGN.md): текст + визуал в две колонки; крупный плакатный заголовок на весь экран (студии, музыка); шейдерный/видео фон с текстом поверх (контраст проверять по самой светлой точке); неожиданная композиция из DESIGN.md. Не центруй всё по умолчанию.
Весь герой с кнопкой виден без прокрутки на 375×667. Кнопка с конкретным действием, а не «Начать» / «Узнать больше» (R-15).

## Главное о продукте
Одна **главная** возможность занимает больше места и показана на настоящем интерфейсе; остальные идут списком или короткими блоками разной «массы» (R-14). Сетка карточек допустима, если содержимое действительно однородно, и тогда причина записана.
```
┌ заголовок (липкий) ┐  ┌ главная возможность + скриншот ┐
│ короткое пояснение │  ├ вторая ──────────────────────  ┤
└────────────────────┘  └ третья ──────────────────────  ┘
```

## Как это устроено / процесс
Показывай **настоящий** процесс. Формат определяет процесс: перечень, схема, таймлайн, сравнение «было/стало» (только с реальными данными). Без круглых иконок с цифрами по умолчанию.

## Демо и работы
Видео-петля 5–8 с (`muted loop playsinline`, пауза при reduced-motion), интерактивный пример, реальные скриншоты в честной рамке. Для портфолио (Experience): работа ведёт, интерфейс отступает; превью при наведении, страницы кейсов с большим содержимым.

## Условия / цены
Показывай ровно то, что есть. Один тариф, два или пять: сколько есть. Цена крупно с периодом, что входит, как отказаться. Нет цены: «бесплатно» или `[ЦЕНА]`, а не выдумка. Выделяется тот вариант, который служит цели продукта, и причина записана.

## Отзывы, клиенты, цифры
Секции нет, пока нет настоящего материала. Когда есть: цитата с настоящим именем и согласием, ссылка на источник, конкретика («сократили проверку с двух часов до двадцати минут»), а не похвала. Цифры только с источником.

## FAQ
Только настоящие вопросы пользователей этого продукта. На `<details><summary>`, работает без JS и с клавиатуры. Если не знаешь, о чём спрашивают, не создавай.

## Финальный призыв и связь
Конкретное действие и честный канал: `mailto:`, реальная форма с рабочим бэкендом и подтверждением, ссылка на бота. Форма без места, куда уйдут данные, не создаётся (R-26). Строка снятия сомнений («Без карты») только если это правда.

## Подвал
Столько колонок и ссылок, сколько реально есть: название, контакт, юридические ссылки на существующие страницы (политика конфиденциальности и оферта обязательны, если собираются данные или принимается оплата), год и юрлицо при необходимости.

## Состояния (R-27)
Везде, где показываются данные: пустое, загрузка (скелетон или индикатор после 300 мс), ошибка («что случилось и что делать», без стека). Пустые экраны предлагают следующий шаг.

## Страницы-спутники
404 с путём назад, страница «спасибо» после формы, политика конфиденциальности простым языком.

## Приложения и дашборды (режим Operate)
Скорость и однообразие важнее выразительности. Не оболочка «сайдбар + верхняя панель + четыре карточки со статистикой» по умолчанию; не карточки статистики с выдуманными числами; не лента активности-наполнитель; график только если на него есть вопрос. Колонки таблиц и поля показывают реальные данные.

## Telegram Web App / мини-приложение
Цвета из `Telegram.WebApp.themeParams`, безопасные зоны и клавиатура, действие внизу (системная MainButton или своя 48 px), переходы между экранами ≤ 200 мс, никаких hover-зависимостей, виброотклик через `HapticFeedback`, кнопка «назад» системная.
