# web-design

Личный плейбук владельца для сайтов. Правила здесь **обязательные**, порядок не менять. Язык общения: русский. Тексты на самом сайте пишутся на языке проекта.

## Порядок работы

### Шаг 0. Вдохновение на 21st.dev и Dribbble (правило владельца, делать ВСЕГДА первым)

Перед любыми решениями по дизайну найди примеры **на обоих сайтах**: 21st.dev (живые компоненты с кодом) и dribbble.com (дизайн целых экранов и брендов от дизайнеров). **Покажи их владельцу** и скажи, как, по-твоему, должен выглядеть сайт, который он просит. Искать можно всё: лендинги, секции, герои, кнопки, меню, карточки, фоны, анимации, логотипы.

1. Из брифа выбери 2–4 английских запроса-тега (`hero`, `pricing`, `navbar`, `shader background`, `scroll animation`, `button`, `dashboard`, `testimonials`, `footer`). Для Dribbble добавь 1–2 запроса про продукт целиком (`vpn landing page`, `music app`, `saas dashboard dark`).
2. **21st.dev** текстом, без авторизации: `curl -sL "https://21st.dev/community/components/s/<тег>.md"` (список по 60 штук с названием и автором). Выбери 4–8 подходящих. По каждому открой `…/@автор/components/<имя>.md`: описание, **лицензия**, зависимости. Визуально: открой `https://21st.dev/community/components/s/<тег>` и 2–4 страницы выбранных компонентов во встроенном браузере (`navigate`), подожди 2–3 с, сними скриншоты. Страница открывается долго, вес ~2 МБ.
3. **Dribbble** только во встроенном браузере: на `curl` сайт отвечает защитой от ботов (код 202, пустое тело). Открой `https://dribbble.com/search/<запрос-через-дефисы>`, подожди 3–4 с. В окне cookie нажми **«Reject All»**. Список работ: `[...document.querySelectorAll('a[href^="/shots/"]')]` (≈40 на странице). Открой 2–4 подходящие работы (`/shots/<id>-<название>`), сними скриншоты, запиши автора. Работы с плашкой PRO и рекламные блоки пропускай. `robots.txt` поиск разрешает; не лезь в разделы, которые он закрывает (`/shots/*/comments`, `/messages` и т.п.), не логинься.
4. **Покажи владельцу** скриншоты и ссылки с обоих сайтов и объясни своё видение: какая структура, какое настроение, какая палитра и шрифты, что берёшь из каждого примера и чего нет. Можно приложить быстрый эскиз (HTML-макет или схема). Спроси один вопрос: что из этого нравится, что нет.
5. Это только вдохновение: чужой код не копировать без проверки лицензии автора, чужой внешний вид не воспроизводить (R-30). У работ на Dribbble кода и лицензии нет вообще: это чужой дизайн, из него берём приём (композицию, приём со светом, ритм), а не картинку. Если один из сайтов недоступен, скажи об этом и предложи замену (awwwards.com, godly.website, land-book.com), не молчи.
6. Использованные ссылки идут в раздел «Референсы» файла `DESIGN.md`.

### Шаг 1. Фильтр antislop (применять всегда)

Загрузи скиллы `antislop` (ядро, 38 правил R-01…R-38) и по задаче: `antislop-ui`, `antislop-copywriting`, `antislop-human`, `antislop-layoutmobile`. Это фильтр, а не стиль: направление даёт DESIGN.md.
- **Режим**: создание нового = `during` (правила применяются по ходу, в конце Delivery Gate); проверка готового = `after` (нумерованный список находок в `anti-slop/audit-001-ГГГГ-ММ-ДД.md`, исправляю только то, что одобрит владелец). Если непонятно, спроси один раз.
- В начале скажи: `antislop active: <режим> (session override|global preference).`
- Жёсткие правила, которые нельзя нарушать: без тире «—» в тексте (R-02), без выдуманных цифр, отзывов, клиентов, гарантий и FAQ (R-17, R-18, R-28, R-36, R-38), без ссылок «в никуда» и мёртвых кнопок (R-24, R-26), контраст AA (R-25), клавиатура и фокус (R-32), честный адаптив (R-03), ничего не создавать за владельца без подтверждения: логотип, фото людей, цифры, структуру меню (R-23).

### Шаг 2. DESIGN.md (составлять ВСЕГДА, до вёрстки)

Скопируй `templates/DESIGN.md` в корень проекта и заполни: Design Read, dials (ENERGY / RHYTHM / MOTION, 1–3), бриф, идентичность и мотив-подпись, референсы (из шага 0), палитра с причиной каждого цвета, шрифты (с кириллицей) с причиной, композиция по секциям (зачем секция и есть ли для неё реальный материал), компоненты, движение с целью каждой анимации, голос текстов, навигация, состояния, открытые вопросы к владельцу. У каждого решения причина в одну строку (R-31).
- Агент составляет файл сам по брифу, референсам и ответу владельца. Честно предупреждай: направление, придуманное агентом, склонно к усреднённому вкусу, поэтому владелец имеет право вето. Не выдумывай факты о продукте.
- Покажи DESIGN.md владельцу, получи «ок» (или правки), и только потом собирай. Если «ок» нет и спросить нельзя: статус «черновик без направления», dials ENERGY 1 / RHYTHM 1 / MOTION 1, сайт не считается готовым (R-37).
- Для существующего проекта сначала прочитай уже имеющийся DESIGN.md и обнови, а не перезаписывай.

### Шаг 3. Сборка

- Токены: `templates/tokens.css` (палитра, текучая типографика, отступы 4/8, радиусы, кривые, фокус, кнопки, reduced-motion). Подставь палитру и шрифты из DESIGN.md.
- Каркас: `templates/landing.html` (честный каркас без выдуманного содержимого). Шейдерный фон: `templates/shader-bg.js` (без зависимостей, пауза вне экрана, reduced-motion, запасной вариант).
- Структура по реальному содержимому, а не по шаблону порядка секций: `references/sections.md`.
- Мобильная версия первой; проверки на 375, 768, 1024, 1440.
- Анимации: GSAP + ScrollTrigger + Lenis, CSS scroll-driven, View Transitions, шейдеры: `references/motion.md` и скиллы `gsap-*`, `threejs-*`.

### Шаг 4. Проверка и Delivery Gate (обязательно)

1. Запусти сайт (`preview_start` или `python3 -m http.server`), сними 375 / 768 / десктоп (подожди 2–3 с или раскрой `[data-reveal]`), проверь консоль, горизонтальную прокрутку, клавиатуру, обе темы, `prefers-reduced-motion`.
2. Кликни **каждый** интерактивный элемент и запиши результат («кнопка → ведёт на #contact, ошибок нет», R-35).
3. Контраст: `python3 ~/.claude/skills/antislop-human/contrast-check.py "#текст" "#фон"`.
4. Выдай отчёт Delivery Gate: PASS/FAIL по четырём блокам с доказательством у каждого PASS (формат в ядре `antislop`). Любой FAIL, значит не сдавать: исправить и прогнать снова.
5. Проверку делай пачкой: один раунд, исправь всё сразу, один повторный раунд, стоп.

### Шаг 5. Сдача

Скриншоты трёх ширин, отчёт Delivery Gate, список оставшихся заглушек `[...]` с вопросами к владельцу, обновлённый журнал решений в DESIGN.md.

## Подкоманды

- `/web-design new <описание>`: шаги 0 → 5 целиком.
- `/web-design audit <путь или url>`: режим `after`, нумерованный список находок с правилом R-XX и приоритетом (Hard Gate = высокий, Purpose-Gate = средний, Quality Locks = низкий), формат «До / После / Почему» для правок; шаг 0 по желанию.
- `/web-design palette <настроение>`: 2–3 палитры из `references/palettes.md` + поиск `ui-ux-pro-max`, с контрастом и причиной.
- `/web-design motion <что анимируем>`: решение по порядку из `references/motion.md` (нужна ли анимация, зачем, кривая, длительность) и код.
- `/web-design shader <идея>`: шейдерный фон или эффект, дисциплина производительности.
- `/web-design design-md`: только составить или обновить DESIGN.md.

## Мелочи, которые легко забыть

- В русских текстах: «ёлочки», неразрывные пробелы после коротких предлогов и между числом и единицей, `lang="ru"`, `text-wrap: balance` для заголовков. Тире «—» не ставить (R-02): запятая, двоеточие, точка, скобки.
- Шрифты проверять на кириллицу: Space Grotesk, Bricolage Grotesque, Fraunces, DM Sans, Syne, Figtree, Outfit, Sora, Urbanist, Lexend не подходят; Plus Jakarta Sans и Hanken Grotesk рисуют только `cyrillic-ext`.
- Широкие шрифты (Unbounded) на 375 px переполняют контейнер первыми: проверять самое длинное слово заголовка.
- Тёмная тема, неоновые и фиолетово-синие палитры, bento, три тарифа, плашка «Популярный» это дефолты ИИ: допустимы только с записанной причиной.
- Образцы с 21st.dev и Dribbble: у 21st.dev смотреть лицензию; у Dribbble лицензии на использование нет вовсе, берём только приём. Не копировать чужой вид, не выдавать за своё.
